# 机器人接触按钮流程（仅 Gazebo）

日期：2026-09-22。此功能与旧孵育箱双循环独立；不得用于真机。
本次新增接触传感器和独立双臂按压流程，不修改机器人URDF、孵育箱authority或920箱子版本。

## 实际触发方式

- 左手Dex1第一指末端接触蓝按钮，右手Dex1第二指末端接触绿按钮。
- 由Gazebo物理引擎的contact sensor报告实际碰撞对和接触深度，再交给原按钮/设备互锁。
- 仅接受指定指尖与对应按钮帽的接触；底座、其他物体或错误手指不触发。
- 接触连续40 ms仿真时间触发一次，离开150 ms后才允许再次触发，持续按住不连发。
- 按钮帽目前是刚性接触开关，没有新增弹簧行程或真实电气按钮模型。
  不是仅按末端距离触发，也不由流程脚本直接发送正常开盖/启动请求。
- 物理接触消息接口依据[Gazebo Harmonic contact sensor](https://gazebosim.org/docs/harmonic/sensors/)。

## 顺序和计时

fresh场景默认盖子闭合，因此先由机器人按蓝按钮开盖准备。正式任务随后执行：

1. 左手接近蓝按钮、接触关闭、撤回，等盖子完全关闭。
2. 右手按绿按钮启动转子，撤离至按钮前的安全等待位。
3. 实测转速首次进入29.8..30.2 rpm后计时30秒**仿真时间**。
   参考首次按压的实测延迟调度第二次绿按钮接触；验收停止接触落在30.0..30.3秒。
4. 右手按绿按钮停止并撤回，等待实测和指令转速均满足原停转门。
5. 左手按蓝按钮开盖到120°并撤回；双臂回到初始姿态。

正常任务只发布左右手臂轨迹，不发布腿部、躯干、夹爪开度或support命令。
紧急失败路径可发转子false并发布实测姿态hold，但不得计作正常任务成功。
开始操作后请勿同时鼠标点击按钮、发布其他轨迹或关闭/重置仿真。

## 规划与准入

- 原URDF、原SRDF和原STL；用MoveIt FK/FCL与SciPy约束IK生成、逐点验证双臂路径。
- 先向后撤离/抬升，再移到按钮前，避免从出生手位直线穿过前面板。
- 桌子、机身及0/30/60/90/120°盖子姿态纳入碰撞模型；非目标物体净距门5 mm。
- 只允许本次指尖与对应按钮帽接触，目标几何压入量0.5 mm，live超过2 mm中止。
- 两处固定安装几何重叠（相机/雷达与躯干）按固定装配处理，不改正式SRDF。
- 腿部在固定pelvis的原Gazebo模型中会自然沉降；必须用实测静止腿姿参与重新审计，
  fresh实测仍须通过原0.02 rad起始一致性门，不把配置文件的零角误当实测零角。
- 机器人关节、clock、接触状态、定位与设备状态陈旧/异常即stop-and-hold。
- 开盖演示例外不可与机器人按压模式同时启用，仍必须先关盖才能启动。

## 入口与证据

功能开关是lab_scene.launch.py的enable_robot_press:=true，默认false；开关只启用传感触发，
不会自动发机器人轨迹。每次运行必须创建全新非覆盖身份，先保护检查、规划审计、隔离构建/
测试，再启动fresh场景并运行centrifuge_robot_cycle.py；execution_claim.json防止复用。
正常演示入口不自动执行机器人。

r117在实际按压前被初始脚踝零角比较拦截，保持停止并退出，不是操作PASS。
r118虽接触帽面，但contact话题错误而超时保持，未开盖/启动；失败证据保留。
Gazebo Harmonic Contact系统读取contact/topic，不是sensor/topic；r119修正并增加回归断言。
